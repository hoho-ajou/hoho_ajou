# 하위 이슈(Sub-issue) 공통 스키마 — Epic 직속 (PM/전체)

특정 역할(R1~R4)에 속하지 않는, 총괄이 담당하는 전체 조율 작업을 쪼갠 하위 이슈입니다. 예: 오케스트레이션 흐름 문서화, 팀 차원 결정 확정, CODEOWNERS·브랜치 전략 실제 반영. 역할별(모듈) 작업은 이 문서가 아니라 [`docs/contracts/subissue_schema.md`](subissue_schema.md)를 따릅니다.

이슈 구조: 전체 Epic(#1) → 하위 이슈(지금 이 문서). **Epic(#1)을 직접** 참조합니다 — 역할 상위 이슈를 거치지 않습니다.

## 필수 섹션 (순서 고정)

```markdown
## 상위 이슈
Relates to #1

## 작업 내용
(무엇을 정리·결정·반영하는지 구체적으로. "이슈 정리"가 아니라
"docs/governance/OWNERSHIP.md에 R2~R4 실제 담당자 반영하고 .github/CODEOWNERS 갱신" 수준)

## 범위 (포함 / 제외)
- 포함: (이 하위 이슈가 실제로 다루는 범위)
- 제외: (헷갈릴 수 있는 인접 작업 중 이 이슈에서는 안 하는 것)

## 완료조건 (Acceptance Criteria)
- [ ] (확인 가능한 조건)
```

## 필드 규칙

| 필드 | 규칙 |
|---|---|
| 제목 | `[PM]` 접두사. 브랜치명은 `CONTRIBUTING.md` 규칙대로 `pm/<이슈번호>-<설명>` |
| 작업 내용 | 어느 문서·설정을 어떻게 바꾸는지 구체적으로 — "코드 함수 시그니처" 대신 "어느 문서의 어느 섹션" 수준 |
| 범위 | 다른 PM 하위 이슈와 겹치지 않게 |
| 완료조건 | 확인 가능한 조건. 코드가 아니므로 "입력/출력 예시"·"엣지케이스"는 필수 아님(해당되면 자유롭게 추가) |
| 크기 | 하위 이슈 하나가 리뷰 가능한 PR(또는 단일 커밋) 1개 분량을 넘지 않도록 쪼갬 |

참고자료는 별도 섹션 없이 필요하면 작업 내용 안에 인라인 링크로 넣는다.

## GitHub Issue로 옮길 때

- 제목에 `[PM]` 접두사만 유지 (라벨은 쓰지 않음 — `CONTRIBUTING.md` 참고)
- `Depends on #`으로 선행 이슈 명시
- Epic(#1)에 체크리스트 항목으로 연결 (GitHub의 tasklist 문법 사용 가능)
