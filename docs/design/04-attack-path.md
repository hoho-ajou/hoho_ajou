# Attack Path Engine 설계 (04-attack-path.md)

> 담당: 전선재 (R4) · 상위 이슈 #12
> 상태: 설계 초안 (작성 중)

## 1. 개요
- 목적: R1(의존성)·R2(위험도)·R3(ML) 출력과 에이전트 권한 정보를 하나의 그래프로 연결해, 공급망 공격이 실제로 악용 가능한 경로를 식별·우선순위화한다.
- 범위(포함): 그래프 구조 정의, 경로 탐색, 우선순위화, 권한 데이터 구조
- 범위(제외): 그래프 DB 도입, 실제 코드 구현, 실시간 처리

## 2. 그래프 데이터 모델
### 2.1 노드(Node)
| 타입 | 설명 | 주요 속성 |
|---|---|---|
| package | 오픈소스 패키지 | id(`pkg:name@version`), risk_score, cve |
| agent | AI 에이전트 | id, framework |
| tool | 에이전트가 사용하는 도구 | id, name |
| permission | 권한·리소스 | id, scope, sensitivity |

### 2.2 엣지(Edge)
| 타입 | 의미 |
|---|---|
| depends_on | 패키지 의존 관계 |
| loads | 에이전트가 도구를 로드 |
| grants | 도구가 권한을 부여 |
| can_access | 권한이 리소스에 접근 |
| can_exploit | 악용 가능 관계 |

### 2.3 노드 식별(id) 규칙
- 형식: `pkg:name@version`, `agent:*`, `tool:*`, `perm:scope`
- R1·R2·R3와 동일한 규칙 사용 (미합의 시 데이터 연결 불가)

## 3. 입력 계약 (R1·R2·R3 → 엔진)
- R1: 노드·엣지 (그래프 구조)
- R2: node_id별 위험도(CVE/CVSS 기반)
- R3: node_id별 ML 악성 점수
- → node_id 기준으로 병합해 각 노드에 위험도 속성 부여
- 상세 스키마는 R4-1 참조

## 4. 공격 경로 탐색
- 진입점: 취약·악성 패키지 노드
- 목표: 민감 권한·데이터 노드
- 방식: 진입점 → 목표 도달 가능 경로 탐색 (도달 가능성, BFS/DFS 개념)
- 처리: 사이클 방지, 중복 경로 제거

## 5. 우선순위화
- 경로 위험 점수 = 경로 상 노드 위험도(CVE·ML)의 가중 합 + 권한 민감도 반영
- 대표 공격 경로 선별 (목표: 20건+)
